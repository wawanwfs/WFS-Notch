# Security and privacy

- **Data:** tasks, notes, calendar events, settings and backups are stored locally. New task priority and optional due timestamp are saved in the same local state/backups, and older tasks remain readable (default Normal, no due time). Due times do not cause background notifications unless explicitly implemented/consented in a future phase. No account or central telemetry.
- **Windows media:** read from supported GSMTC sessions; data is shown locally. Album artwork is accepted only when the player provides a limited-size PNG/JPEG/GIF thumbnail. Windows application IDs are not unique per tab/player instance: WFS now detects duplicate IDs and denies targeted controls or snapshots rather than accidentally controlling another tab. Enumerations larger than 64 sessions and unreadable identities fail closed. No additional OS privileges, media capture or network use. Headless Chromium mocks do not prove behavior on real Windows players.
- **Notifications:** only WFS-created calendar reminders. Disabled by default, redacted titles by default, and optional WFS-only pause mode. The native 20-second scheduler runs only while the WFS Notch process is running, requires opt-in on every dispatch, never scans third-party notifications, and does not persist private titles in logs. Reminder attempts are reserved in a title-free ledger in the app's local state before enqueue and retained for a bounded period across restarts. A platform API rejection now records an anonymous bounded backoff state (up to three total sender attempts) and removes the reservation in the same atomic transaction. Once the limit is reached, WFS suppresses further attempts for that unchanged event; confirmed enqueue retains a durable reservation. The retry journal survives app restart and backup restore and stores no event titles, although the existing reservation key can contain a source UID. Delivery errors are logged generically without private titles or raw Windows error strings. This provides best-effort at-most-once enqueue attempts, not exactly-once visible delivery; a crash after reservation but before the OS accepts a toast can result in a missed notification. Backup restore preserves the current delivery journal. WFS does **not** intercept notifications from other apps or alter Windows global Do Not Disturb.
- **Calendar:** ICS import is limited to 256 KiB and 250 expanded events. Timed TZID input uses local IANA conversion; floating times require explicit user choice and DST gaps/overlaps fail closed. DATE/DTEND all-day events persist as civil start/exclusive-end dates with a UTC-midnight storage anchor only, no timezone conversion on screen and no implicit midnight notification. Bounded DAILY/WEEKLY/MONTHLY/YEARLY recurrence with supported BYDAY/BYMONTH/BYMONTHDAY/WKST selectors and EXDATE/RDATE is materialized with stable occurrence IDs; new imported series also persist versioned source DTSTART/DTEND/DURATION, original rule, exception inputs and modified occurrence IDs in the local app state/backups. Legacy flattened instances are not reverse-inferred. Rename/delete-series commands are scoped to an imported series. Removing an imported occurrence or series now records a bounded title-free local cancellation key; repeated ICS imports skip that key. Clearing cancellation history requires an explicit confirmation and does not itself reimport data; backup restore may intentionally change both events and cancellation markers. Strict timed DTEND and positive DURATION values are converted into UTC exclusive ends, with 366-day maximum and DST gap/overlap validation. Recurring timed events preserve elapsed duration per occurrence after timezone-resolved starts (the original RRULE is still flattened). RECURRENCE-ID, unsupported complex BYSETPOS, unbounded or oversized recurrence and unsupported mixed types are rejected, not silently truncated. For untouched ICS source series, export now regenerates and verifies the master against every persisted occurrence before retaining one RRULE/EXDATE/RDATE VEVENT. Edited, canceled, missing, untrusted or legacy occurrences are flattened with no regenerated master, preventing accidental resurrection. Full-series schedule reflow and faithful RECURRENCE-ID override export are not implemented. No external ICS uploads. No calendar network sync, OS calendar modification or external file access.
- **Display:** enumeration and local positioning only, with optional read-only foreground fullscreen rectangle checks. A unique bounded monitor name may be stored locally to preserve the selected display across coordinate/DPI rearrangement; duplicate, unavailable or unsafe display names fall back to coordinate identifiers, with saved legacy origin selection preserved. No admin privileges, input hooks, process-title collection, OS monitor configuration changes, or device-name uploads.
- **IPC:** Tauri capabilities limit frontend access. User-provided links are constrained to HTTP(S). Do not store secrets or remote management credentials in this repository.
- **CI:** read-only workflow token, no public tunnel, no shell exposed from a runner, no original Poni installers, no raw Ghidra pseudocode or reference executables.

## Known limits

Unverified Windows hardware behavior, unsigned installer, no independent penetration test, and limited privacy controls on external services requested by the user. Some focus/calendar reminders are in-app only unless the native app is running.

## Windows installer reproducibility

CI fetches the official NSIS 3.13 bundle and Tauri NSIS utility DLL only from Tauri's own GitHub Releases/API, checks their upstream-pinned SHA-1 digests, and uses the per-user Tauri cache. This is an integrity match to Tauri's bundled pins, **not** a replacement for code signing or stronger artifact attestations. Downloads are retried to mitigate GitHub CDN 504 errors; unsigned installers remain explicitly labeled.
